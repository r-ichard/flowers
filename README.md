# 🌻 AI Field of Flowers — an LLM benchmark

A benchmark of flowers **generated by LLMs**, growing on the web. Each flower is
a single SVG a model produced; clicking it shows which model, the prompt, and how
long it took. **Anyone can add one** with a pull request — see
[CONTRIBUTING.md](./CONTRIBUTING.md).

The whole idea: contributing should be as easy as dropping one `.svg` file into
[`flowers/`](./flowers). No registry, no wiring — the site finds it automatically.

## How it works

```
flowers/*.svg  ──▶  loader (import.meta.glob)  ──▶  parseFlower (validate)  ──▶  <FlowerGrid> ──click──▶ <FlowerDetailPanel>
   one file            build-time discovery         benchmark header + safety     grid of blooms       model / prompt / notes
   per flower
```

- **`src/flowers/parseFlower.ts`** — the one piece of real logic. Reads the
  `<!-- name / author / model / prompt / comment / github -->` header, enforces
  the `viewBox="0 0 255 255"` canvas, and rejects unsafe SVG (`<script>`, inline
  event handlers, `javascript:` URIs). Pure and mutation-tested.
- **`src/flowers/loader.ts`** — discovers every `flowers/*.svg` at build time via
  Vite's `import.meta.glob` and parses each one. The thin glue.
- **`src/components/`** — `FlowerGrid` lays the field out as 255×255 tiles of
  clickable top-down flowers; `FlowerDetailPanel` opens on click (left side on
  desktop, full-screen on mobile) with the flower big + its benchmark data. Each
  tile nods gently so even a static SVG feels alive.

Contributors provide a `255 × 255` top-down flower plus the benchmark data
(model, author, prompt, and a note on the process). See
[CONTRIBUTING.md](./CONTRIBUTING.md).

## Develop

```bash
npm install
npm run dev            # start the dev server
npm test               # run the test suite
npm run build          # type-check + production build
```

| Script              | What it does                                                    |
| ------------------- | --------------------------------------------------------------- |
| `npm run dev`       | Vite dev server with hot reload.                                |
| `npm test`          | Vitest — unit, component, and the `flowers/` contribution gate. |
| `npm run typecheck` | `tsc --noEmit`.                                                 |
| `npm run lint`      | ESLint.                                                         |
| `npm run format`    | Prettier (write). `format:check` in CI.                         |
| `npm run mutation`  | Stryker mutation testing on the pure parser.                    |
| `npm run build`     | Type-check then build to `dist/`.                               |

## Testing & CI

Tests follow the [engineering guidelines](./AGENTS.md): the pure parser was
built test-first and is audited with **mutation testing**; components are covered
with Testing Library; and a **contribution gate** validates every real file in
`flowers/`. GitHub Actions runs format, lint, typecheck, tests, and build on
every pull request.

## Deploy

The site is static. Netlify builds and deploys it through its native Git
integration, with a Deploy Preview for every pull request — so a new flower can
be seen in the field before it merges. Config lives in
[`netlify.toml`](./netlify.toml).
