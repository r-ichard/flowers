# Add a flower to the experiment 🌱🤖

This is an experiment in flowers **generated by LLMs**. You ask a model to draw a
flower as an SVG, then submit it here with the model and a short author's note
on how it went. Nothing is scored — the point is what you can make and whether
you enjoyed making it. One file, one pull request.

## The fastest way: hand your LLM the prompt below

The [copy-paste prompt](#copy-paste-prompt-for-your-llm) at the bottom tells a
model everything it needs — the specs, the exact header, where to save the file,
the security rules, and the checks to run. Paste it into your coding assistant,
fill in your name, and open a pull request.

## What a flower is

- **A flat SVG on a 255×255 canvas.** The `<svg>` must declare
  `viewBox="0 0 255 255"`.
- **Seen from above.** Top-down bloom, no stem — just the flower head.
- **With every `id` prefixed by the file name.** In `blue-poppy.svg`, ids read
  `blue-poppy-petal`, `blue-poppy-center`. Every flower is inlined into the same
  page, so two flowers sharing one id make `href="#id"` and `url(#id)` resolve to
  the wrong flower's shape.
- **With an experiment header** naming the model, you, and an author's note (`comment`).

## The experiment header

Put this comment at the very top of the file, above the `<svg>`:

```svg
<!--
  name: Bluebell
  author: Your Name
  model: claude-opus-4-8
  comment: Worked on the first try; adjusted the blue once to look less flat.
  github: your-handle
-->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 255 255">
  <!-- ...the flower the model produced... -->
</svg>
```

| Field     | Required | Notes                                                                                                  |
| --------- | -------- | ------------------------------------------------------------------------------------------------------ |
| `name`    | yes      | The flower's display name.                                                                             |
| `author`  | yes      | You — the person who ran the model.                                                                    |
| `model`   | yes      | The LLM that generated it (e.g. `claude-opus-4-8`).                                                    |
| `comment` | yes      | Your note on the process: attempts, tweaks, and any prompting details you want to highlight. One line. |
| `github`  | no       | Your GitHub handle (or a full profile URL) — links your name.                                          |

There is no separate prompt field. If you want to highlight how you prompted the
model — a useful instruction, an iteration, or an approach — include it in your
author's note (`comment`). You do not need to reproduce the full prompt.

Keep each field on **one line**. Copy any file in [`flowers/`](./flowers) (for
example [`daisy.svg`](./flowers/daisy.svg)) as a starting point.

## Submitting via GitHub (fork → branch → pull request)

You don't have write access to the main repo, so you contribute from your own
**fork**. If you're new to this, the flow is:

1. **Fork** [`r-ichard/flowers`](https://github.com/r-ichard/flowers) — click
   **Fork** (top-right on GitHub). You now have your own copy at
   `github.com/<your-username>/flowers`.
2. **Clone** your fork and create a branch:
   ```bash
   git clone https://github.com/<your-username>/flowers.git
   cd flowers
   git checkout -b add-<flower-name>
   ```
3. **Add your flower** to the `flowers/` folder (or let your LLM do it with the
   [prompt below](#copy-paste-prompt-for-your-llm)).
4. **Check it locally:**
   ```bash
   npm install
   npm test
   ```
5. **Commit and push** to your fork:
   ```bash
   git add flowers/<flower-name>.svg
   git commit -m "Add <flower-name> flower"
   git push origin add-<flower-name>
   ```
6. **Open the pull request** against `r-ichard/flowers` `main`. GitHub shows a
   "Compare & pull request" button after you push, or run
   `gh pr create --repo r-ichard/flowers`.

**No git? Use the browser.** On your fork, click **Add file → Upload files** (or
**Create new file**), drop your `.svg` into `flowers/`, commit to a new branch,
and GitHub walks you straight into opening the pull request — no local setup.

## What CI checks

When you open the pull request, GitHub Actions runs the project's checks. For your
flower specifically, `tests/flowers.test.ts` reads every file in `flowers/` and
confirms yours has all required fields, is a real SVG on the `viewBox="0 0 255 255"`
canvas, is safe (no `<script>`, inline `on...=` handlers, or `javascript:` URIs),
has a unique file name, and shares no `id` with another flower. If something's
off, the failure message names the exact reason. Netlify also builds a **preview** so reviewers see your flower in the
field before it merges.

## Copy-paste prompt for your LLM

Paste this to your coding assistant (or any LLM). Replace **YOUR NAME** and, if
you like, **YOUR GITHUB HANDLE**; the model fills in the rest.

```text
You are contributing one flower to an open-source experiment in LLM-generated SVG
flowers. Produce a single self-contained SVG file and nothing else.

SPECIFICATIONS
- The drawing is a FLOWER SEEN FROM DIRECTLY ABOVE (top-down bloom, no stem, no
  ground, no background) — just the flower head.
- The root <svg> MUST declare viewBox="0 0 255 255" and xmlns="http://www.w3.org/2000/svg".
- Draw within the 255×255 canvas, centered on roughly (127.5, 127.5), leaving a
  small margin so nothing clips at the edges.
- Use only flat vector shapes (path, circle, ellipse, rect, polygon, g, use with
  a LOCAL #id, linearGradient/radialGradient). Keep it clean and readable.
- Every id MUST be prefixed with the file's kebab-case name, because all flowers
  are inlined into one page and ids are a shared namespace: in blue-poppy.svg
  write id="blue-poppy-petal", not id="petal", and reference it as
  href="#blue-poppy-petal" / url(#blue-poppy-petal). A bare id like "petal"
  silently steals another flower's shape and fails the contribution gate.

SECURITY — the file is inlined into a web page, so it MUST be safe:
- NO <script> tags.
- NO inline event handlers (no attribute beginning with "on", e.g. onload, onclick).
- NO "javascript:" URIs anywhere.
- NO external references: no <image>, no <foreignObject>, no href/xlink:href to
  any URL or file (only local "#id" references via <use> are allowed).
- No network requests, no embedded HTML, no external fonts.

HEADER — put exactly this comment at the very top of the file, above the <svg>,
filling every field on ONE line each:
<!--
  name: <a short display name for the flower>
  author: YOUR NAME
  model: <the exact model id you are, e.g. claude-opus-4-8>
  comment: <your human author's note about the process, optionally highlighting prompting details. Ask them to write it>
  github: YOUR GITHUB HANDLE   (delete this line if you don't want it)
-->

DELIVERABLES
1. Save the file as flowers/<kebab-case-name>.svg in this repository (e.g.
   flowers/blue-poppy.svg). The name (without .svg) must be unique in that folder.
2. Then run the project's checks and show me the result:
   - `npm install` (first time only)
   - `npm test` — this runs the contribution gate that validates the new flower;
     it must pass. If it fails, read the message, fix the file, and re-run.
   - `npm run dev`, then open the printed local URL so I can SEE the flower
     rendered in the field (or open the .svg file directly in a browser).
3. Report: the file path, that `npm test` passed, and a one-line description of
   how the flower looks.
```
